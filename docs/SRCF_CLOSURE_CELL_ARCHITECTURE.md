# SRCF Closure-Cell Architecture

Дата: 2026-06-22  
Репозиторий: `maxwelhelp/srcf-pregeometry-lab`

## 1. Главный вопрос

Это уже не вопрос “где применить SRCF”.

Главный вопрос:

```text
можно ли заменить сам принцип нейрона / слоя?
```

Обычная нейросеть строится вокруг идеи:

```text
нейрон = маленький аппроксиматор

y = activation(w · x + b)
```

SRCF предлагает другой принцип:

```text
ячейка = маленькая система самозамыкания
```

Она не просто выдает число. Она проверяет:

- согласовано ли состояние;
- куда оно сходится;
- восстанавливается ли оно после шума;
- входит ли оно в basin;
- что надо поправить, чтобы состояние стало самосогласованным.

Такой элемент лучше называть не нейроном, а:

```text
closure-cell
basin-cell
self-closure unit
relation-consistency cell
```

## 2. В чем новый принцип

Обычный нейрон спрашивает:

```text
насколько вход похож на мой шаблон?
```

Closure-cell спрашивает:

```text
если я применю себя к этому состоянию несколько раз,
оно стабилизируется?
оно восстанавливается?
оно схлопывается?
оно входит в мой basin?
какие отношения надо поправить, чтобы оно стало согласованным?
```

Обычный нейрон — это детектор признака.

Closure-cell — это:

```text
детектор согласованности
исправитель состояния
basin detector
relation repair unit
```

Это реально другой принцип вычисления.

## 3. Как выглядел бы “нейрон” на этом принципе

Обычный нейрон:

```text
y = gelu(x @ W + b)
```

Closure-cell:

```text
h0 = encode(x)
h1 = F(h0)
h2 = F(h1)
h3 = F(h2)

output = {
  state: h3,
  delta: ||h3 - h2||,
  recovery: ||F(h3 + noise) - h3||,
  move: ||h3 - h0||,
  basin_id: descriptor(h3),
  uncertainty: convergence_quality(h0,h1,h2,h3)
}
```

То есть он выдает не только активацию, а:

- стабилизированное состояние;
- насколько оно устойчиво;
- насколько оно изменилось;
- насколько оно восстановимо;
- к какому basin оно принадлежит;
- насколько оно уверенно сошлось.

Это уже не обычный MLP-блок.

## 4. Что это дает

Главное преимущество:

```text
сеть начинает думать не только признаками, а режимами.
```

Обычная сеть строит признаки:

- край;
- цвет;
- форма;
- токен;
- паттерн;
- embedding direction.

Closure-сеть строит режимы:

- это состояние самосогласовано;
- это состояние нестабильно;
- это состояние восстанавливается;
- это состояние слишком схлопнуто;
- это состояние принадлежит basin A;
- это состояние между basin A и basin B;
- это состояние не входит ни в один известный basin.

Это ближе к:

- памяти;
- пониманию структуры;
- восстановлению;
- проверке согласованности;
- итеративному рассуждению;
- контролю неопределенности.

## 5. Нужны ли аппроксиматоры

Да.

Полностью без аппроксиматоров нельзя, если система должна обучаться.

Но роль аппроксиматора меняется.

Обычная сеть:

```text
аппроксиматор сразу выдает ответ
```

Closure-сеть:

```text
аппроксиматор задает правило самоприменения,
а ответ появляется как результат сходимости.
```

То есть MLP / матрицы / attention остаются, но они уже не вся идея.

Они становятся локальным правилом динамики:

```text
MLP не говорит: “это класс 7”.
MLP говорит: “как состояние должно сдвинуться, чтобы стать самосогласованным”.
```

## 6. Какие архитектуры можно построить

### 6.1. Closure-MLP

Замена обычного MLP-блока.

Обычный Transformer block:

```text
Attention -> MLP
```

Closure-блок:

```text
Attention / relations -> Closure iterations -> stable state
```

Смысл:

```text
после attention сеть не просто прогоняет FFN,
а проверяет согласованность отношений между токенами.
```

Что может дать:

- меньше противоречий;
- лучше long-range consistency;
- лучше восстановление потерянного контекста;
- сигнал “не стабилизировалось / не уверен”.

### 6.2. Closure-Attention

Обычное attention делает:

```text
кто на кого смотрит
```

Closure-attention делает:

```text
какие связи после нескольких шагов остаются устойчивыми
какие связи исчезают
какие связи надо восстановить
какой attention graph самосогласован
```

То есть внимание становится не одноразовой матрицей, а динамикой стабилизации графа внимания.

Это может быть сильнее обычного attention там, где важна структура:

- reasoning;
- код;
- длинный контекст;
- планы;
- графы;
- мультимодальные связи;
- RAG consistency.

### 6.3. Closure-Memory

Обычная память:

```text
найди ближайший embedding
```

Closure-memory:

```text
дай неполный / шумный фрагмент отношений
пусть он сойдется к ближайшему самосогласованному basin
верни восстановленную структуру
```

Примеры:

- неполный план -> восстановить полный план;
- неполный граф фактов -> восстановить связную картину;
- шумная память агента -> вернуть согласованную версию;
- частичный кодовый контекст -> восстановить зависимости;
- missing RAG context -> определить, какой факт нужен.

### 6.4. Closure-MoE

Обычный MoE:

```text
router выбирает эксперта
```

Closure-MoE:

```text
вход запускается в несколько closure-basins
какой basin стабилизировался лучше — тот эксперт и нужен
```

Routing становится не просто softmax, а оценкой устойчивости сходимости.

Интерпретация:

```text
не входит ни в один basin -> нужен новый эксперт / новое знание
входит в два basin -> неоднозначность
быстро схлопнулось -> слишком простой / шаблонный случай
плохо сходится -> не хватает данных
```

### 6.5. Closure-Graph Network

Для графов это естественное применение.

Обычная GNN:

```text
передай сообщения по ребрам
```

SRCF-граф:

```text
пусть граф самоприменится
посмотри, какие ребра устойчивы
какие ребра нужны для восстановления
какие подграфы являются basin
```

Это уже не просто node classification.

Это:

- graph repair;
- edge recovery;
- subsystem discovery;
- relation denoising;
- community by closure, not by density;
- graph pretraining без labels.

### 6.6. Closure-Reasoning Core

Рассуждение можно делать не только как текстовый chain-of-thought.

Можно делать:

```text
состояние отношений -> несколько closure-шагов -> stable distinction
```

Это полезно для:

- логических противоречий;
- проверки плана;
- согласованности RAG;
- верификации tool calls;
- поиска “вопрос не определен”;
- определения missing facts;
- раннего отказа от галлюцинации.

## 7. Что принципиально нового

Самое новое не в том, что внутри есть MLP.

Самое новое:

```text
базовая операция сети меняется.
```

Обычная базовая операция:

```text
representation transform
представление -> новое представление
```

Новая базовая операция:

```text
closure transform
состояние -> самосогласованное состояние + диагностика сходимости
```

То есть сеть получает встроенные понятия:

- устойчиво;
- неустойчиво;
- восстановимо;
- невосстановимо;
- схлопнуто;
- различимо;
- неразличимо;
- входит в basin;
- не входит в basin;
- между двумя basin.

Обычные сети могут выучить это косвенно, но не имеют такой механики как базовой операции.

## 8. Что это может дать, если допилить

### 8.1. Самовосстановление

```text
шумный вход -> восстановленное внутреннее состояние
```

Сеть может чинить поврежденные состояния, а не только классифицировать их.

### 8.2. Проверка согласованности

Модель может сказать:

```text
это состояние не сходится
это состояние противоречиво
это состояние слишком быстро схлопывается
это состояние не восстанавливается
```

### 8.3. Более честная неопределенность

Не просто probability 0.57, а:

```text
не вошло ни в один basin
между двумя basin
сходимость плохая
recovery плохой
fixed point неустойчивый
```

### 8.4. Структурная память

Память не по ближайшему вектору, а по восстановлению отношений.

```text
partial relation fragment -> nearest consistent basin -> restored structure
```

### 8.5. Динамические вычисления

Количество шагов можно делать адаптивным:

```text
простое состояние -> 2 шага
сложное / неустойчивое -> 8 шагов
не сходится -> undefined / need more info
```

### 8.6. Меньше галлюцинаций в reasoning

Если ответ / план / context graph не самосогласуется, сеть может не выдавать его уверенно.

## 9. Где это сильнее обычного нейрона

Не везде.

Плохо подходит:

- простая классификация картинок;
- простые таблицы;
- задачи, где достаточно одного forward pass;
- задачи, где ручные признаки уже идеальны;
- дешевые задачи без структуры отношений.

Сильно подходит:

- графы;
- память;
- длинный контекст;
- планирование;
- кодовые зависимости;
- RAG / knowledge graphs;
- мультимодальные связи;
- сенсорные системы;
- восстановление структуры;
- reasoning consistency;
- relation repair.

Это не “замена всем нейронам”.

Это новый тип слоя / модуля для структурных состояний.

## 10. Самая интересная архитектура

Не надо сразу пытаться полностью заменить все нейроны.

Лучший путь — гибрид:

```text
обычные аппроксиматоры = быстро считают локальные признаки
closure-cells = стабилизируют отношения между признаками
```

Общая архитектура:

```text
Input
 -> обычный encoder
 -> relation builder
 -> closure core
 -> readout
```

Для LLM / Transformer:

```text
tokens
 -> embeddings
 -> attention proposes relations
 -> closure layer stabilizes relation graph
 -> MLP/readout
```

Attention говорит:

```text
возможные связи такие
```

Closure говорит:

```text
какие из этих связей самосогласованы
```

Это может стать новым типом Transformer block.

## 11. Фундаментальный прототип: ClosureNeuronLayer

Нужно построить один минимальный слой.

Вход:

```text
X [B, N, D]
```

Построение отношений:

```text
R[i,j] = relation(x_i, x_j)
```

Closure:

```text
R* = F^T(R)
```

Возврат:

```text
X_new = aggregate(R*, X)

diagnostics = {
  contract,
  h_contract,
  recovery,
  fixed,
  move,
  far_keep,
  basin_id,
  uncertainty,
  closure_curve
}
```

Сравнивать с:

- MLP;
- Attention;
- GNN layer;
- recurrent layer;
- graph autoencoder.

Тестовые задачи:

- copy / recovery;
- graph repair;
- edge recovery;
- sequence consistency;
- reasoning toy tasks;
- long-context consistency;
- RAG contradiction toy;
- plan consistency toy.

### 12.3. Что считать успехом

Не требовать сразу победы везде.

Успех:

```text
ClosureNeuronLayer дает диагностический сигнал,
которого нет у MLP/Attention:
  - не сошлось;
  - восстановилось;
  - между basins;
  - overclosed;
  - underclosed;
  - missing relation.
```

Практический успех:

```text
ClosureNeuronLayer + обычный encoder
лучше, чем обычный encoder,
на задачах repair / consistency / graph closure / RAG consistency.
```

## 13. Короткий вывод

Да, из SRCF-принципа можно сделать новый фундаментальный элемент сети.

Но он не будет “нейрон-аппроксиматор”.

Он будет:

```text
нейрон-самозамыкатель
нейрон-восстановитель
basin detector
closure-cell
relation-consistency unit
```

Его смысл:

```text
не просто посчитать функцию,
а привести состояние к устойчивой самосогласованной форме
и измерить, как оно сходилось.
```

Аппроксиматоры внутри все равно нужны, но они уже не центр идеи.

Центр идеи:

```text
итеративное самоприменение + basin dynamics + diagnostics.
```

Самые интересные архитектуры:

```text
Closure-Transformer
Closure-Memory
Closure-GNN
Closure-MoE
Closure-Reasoning Core
Relation Repair Network
ClosureNeuronLayer
```

Главная новая формула:

```text
вычисление не как один проход признаков,
а как сходимость системы отношений к устойчивому состоянию.
```
